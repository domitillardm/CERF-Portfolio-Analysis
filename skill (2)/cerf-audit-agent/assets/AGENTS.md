# CERF portfolio Codex operating rules
Read `00_START_HERE.md`, `handover.json`, methodology, decisions and validation issues before acting. Assume the reader knows nothing about CERF. Treat all unapproved scores and rules as provisional. Never modify authoritative inputs in place.

For every session: record a session identifier, actor, objective and scope; capture meaningful discussions, attempted/failed experiments, corrections and uncertainties with `scripts/session_log.py`. This is a structured summary, NOT an automatic verbatim conversation archive. Use `scripts/audit_run.py` for each substantive executable analysis, declaring inputs, outputs and rules version. Never say unwrapped work was captured.

For authorised writing sessions, preserve prior documentation and handover, record unresolved questions and provisional decisions, update supported handover facts, and run the installation's `scripts/finish_session.py` with session, actor, summary, next-action and blocker. Read `handover.json.latest_report` for the new versioned status, internal history and unapproved client draft. Keep the root start page and internal guide stable. Do not run the old report generators against the project root; they overwrite documents. Show concrete changes, checks, failures, next actions and logging gaps for review. Do not commit/push without user approval. Read-only tasks must not invoke writers, setup or tests that create files/commits.

Maintain an activity-level audit table with activity ID, dataset version, rules version, AI classification, evidence reference, confidence/uncertainty explanation, validation state, reviewer, correction and timestamp. Never infer that a scoring rationale proves the classification. Use actual evidence and explicit missing-data codes.

CERF tracks are the main analytical unit; activities support country-track analysis in chronological order. Separate achieved results from future potential and result classifications from evidence strength. Reported outcomes are monitoring claims; missing evidence is not proof of no results and frequencies are not success rates. Preserve original AI scores and keep proposed revisions separately traceable. Humans decide final scores and approve methodology. Obtain existing prompts/rules and the exact Inception Report scoring table before proposing revised definitions. The highest-human-checked-score rule per country-track is provisional (CERF-M001), not approved. Establish confidence before independent case-study comparison. Mark external preparation/anonymisation as owner-reported until supporting records are checked.

SharePoint publication, if authorised, is separate from GitHub and cloud snapshots. Codex Cloud task workspaces may be ephemeral. Do not claim sync or access without checking actual uploads and permissions. Prepare publication material only when authorised; require designated human review before client release. Avoid simultaneous edits of authoritative spreadsheets; use assigned ownership and versioned files. Do not store raw interviews, personal information, credentials or confidential links in logs.
